# Web 共用清潔動畫素材 v1

目前共同預覽已切換到[泡沫六格小樣v2](../foam-study-v2/README.md)：其餘五份素材沿用本目錄，實際播放六份圖集／26格。下述28格與8團泡沫配置是v1來源及先前迭代紀錄，保留供追溯；本目錄的分鏡、日夜合成與GIF則已隨共同播放器更新為目前小樣。

2026-10-22，使用者確認 v4 收腰海綿造型與全階段 60 px 基準寬後，審閱並授權六份精靈圖提示。三組子 agent 並行製作，主 agent 統一檢查與組成獨立動畫預覽。

## 圖集與來源

- 海綿：3 格，保留兩端圓胖／兩側內凹收腰、黃色孔洞與斜向厚度；局部受壓再回彈。所有階段用同一繪製比例，原姿態基準寬 60 px，幼年不縮小。
- 泡沫：8 格，少→中→多→中→少，只增減泡沫，不畫擦拭軌跡或地面泡沫堆。
- 蓮蓬頭：靜態 1 格；進出與位置由播放器控制。
- 淋浴水束：6 格，開水／四格出水循環／關水。
- 水滴與水花：5 格，3 欄2列，第6格全透明。
- 乾淨亮點：5 格，3 欄2列，第6格全透明。

共 6 份 PNG 圖集、28 格有效畫格，均由內建 imagegen 產生。來源圖、切格座標／平移／Alpha／SHA-256 與真實生成提示詞分別保留於各組：

- [A 組海綿與泡沫](group-a/README.md)：[海綿提示詞](group-a/sponge-prompt-v1.txt)、[泡沫提示詞](group-a/foam-prompt-v1.txt)。
- [B 組蓮蓬頭與水束](group-b/README.md)：實際提示與來源版本見該目錄。
- [C 組水滴與亮點](group-c/README.md)：[提示詞](group-c/prompts.md)。

整理只裁切、平移與補透明留白，保留框內生成 RGBA；沒有逐格縮放、去背、重畫或改色。原圖透明像素中的 RGB 在工具預覽可能像光暈，判定採真正 Alpha 合成。仍有部分孔洞／泡型逐格重繪差異，不聲稱像素完全一致。

## 播放與預覽

[動畫預覽頁](../../../../cleaning-animation-preview.html) 使用 `cleaning-animation-view.js` 的共用效果播放器、`cleaning-animation-scene.js` 與現有白鳥／小龍正式角色繪圖程式。原有[靜態造型頁](../../../../cleaning-style-preview.html)保留。幼龍仍為既有遮罩版本。

初始節奏共 4.2 秒：0～0.3 秒海綿進場，0.3～1.6 秒擦洗起泡，1.6～2 秒換淋浴道具，2～3.4 秒沖洗，3.4～4.2 秒水滴與亮點收尾。預覽循環另加約 1 秒待機；可暫停、慢速、拖曳時間、切日夜、比較四種現有角色／階段。減少動態採固定海綿與泡沫示意。

使用者進一步限定目前只確認素材與動畫效果，並要求泡沫是很多團、不要只在中間一團。預覽現使用同一泡沫圖集繪製8團小泡群，分布胸腹與身體兩側，成年基準寬22～28 px，幼年位置與泡群沿用角色比例。起泡延遲0～0.49秒，消散另以較短錯開時間讓全部泡群在3.4秒前離場；減少動態也顯示同一多團配置。沒有重畫、改色或修改泡沫PNG，海綿仍維持全階段相同60 px基準。多團修正時蓮蓬頭只有進出場；後續沖洗掃動見下一段。使用者之後指出這種重複泡群不夠自然，泡沫品質尚未確認，目前依指示暫緩重製。

使用者授權先接順完整洗澡預覽：2～3.4秒沖洗採中央→左→右→中央路徑，2.35／3秒轉向，三段均在端點減速至零。掃幅按各角色胸腹寬設定：幼鳥／成鳥約26／32 px，幼龍／成龍約27／35 px（完整左右行程）；水束採原比例與長度以保留噴頭離臉的距離。由同一 `showerPose` 同時計算蓮蓬頭位置、噴口、水束起點與沖洗落點，水滴／水花取生成當刻的落點，離開後沿各自路徑落下。3.4秒關水、3.7秒前收起蓮蓬頭，殘滴先落完，3.72秒起兩顆亮點收尾，4.2秒清空。海綿／泡沫圖源與泡沫配置未改，減少動態沿用固定示意。

`node --test --test-isolation=none web-preview/cleaning-animation-tests.cjs` 4項通過：轉向速度／體型範圍、實際繪製後噴口與水束起點誤差不超過約1px、關水退場與收尾清空、所有階段海綿60px同一比例。四種角色的共同播放器畫面與4份GIF同步重建，尺寸／54格／5240ms回讀通過。這些程式檢查不替代整段節奏或美術確認。

已於瀏覽器查看四種角色的2.35秒[左側轉向](browser-rinse-left.png)、3秒[右側轉向](browser-rinse-right.png)及3.92秒亮點收尾，並恢復正常速度循環。這是本輪有限視覺檢查，整體速度、掃幅、角色反應與美術仍待使用者確認。

使用者再指出海綿也應依體型由上往下、左右擦洗。0.3～1.6秒改為胸腹上方向下方連續右→左→右→左三次擦過，橫向轉折採餘弦減速，縱向緩進緩出；進出場銜接首末位置。左右完整行程依幼鳥／成鳥／幼龍／成龍約32／40／33／42 px，上下約21／26／18／22 px。只調整路徑，所有角色海綿基準寬仍60 px，泡沫圖源與配置保留。

路徑調整後，同一測試指令6項通過，新增涵蓋三次交替擦過、持續向下、體型對應範圍、轉向減速及進出場連續性；原有沖洗與尺度檢查亦通過。分鏡、日夜合成與4份GIF已同步重建，GIF回讀均384×256、54格、5240ms。瀏覽器檢視四種角色0.3秒[上方起點](browser-sponge-top.png)、0.73秒[左側轉向](browser-sponge-left.png)、1.16秒第二次轉向及1.59秒[下方終點](browser-sponge-bottom.png)，並恢復正常循環。此為有限定位與遮擋檢視，擦洗速度、幅度與整體美術仍待使用者確認。

多團版本已重建分鏡、日夜合成與四份GIF，GIF回讀尺寸／54格／5240 ms通過；瀏覽器查看1.95秒的四種角色分布、減少動態配置及3.4秒泡沫全消散，並恢復正常循環。[多團泡沫實際畫面](browser-multi-foam-preview.png)供美術審閱，尚待使用者確認。

素材定位、切格、錨點與名義顯示寬見 `animation-data.json`；原始各組 manifest 保留。海綿僅局部繪製變形與路徑移動，角色不拉伸或縮放。其他物種後續仍須以其正式圖源測試定位和遮擋；全寵物共用的是獨立效果與定位方式，不代表未存在的角色已驗收。

本輪素材先在獨立美術預覽完成確認，2026-10-22 再接入花園主頁正式清潔流程：主頁播放同一 `CleaningAnimationView` 的 4.2 秒效果，完成時才沿用既有 `clean` 指令寫入清潔度與 EXP。獨立預覽本身仍不讀寫寵物存檔；素材接入沒有改 BLE／韌體。

## 重建與驗證邊界

需 Pillow、Node.js 與 `@napi-rs/canvas`：

1. 各組整理腳本可從保留的來源重建 atlas，詳見各組說明。
2. `python tools/prepare_cleaning_animation.py` 合併資料並檢查 6 份 RGBA atlas、有效格、透明空格及尺寸，輸出 `atlas-validation.json`。
3. `node tools/render_cleaning_animation.cjs` 使用共用角色與效果播放器產生分鏡、日夜合成圖，以及系統暫存中的54張連續畫面／角色。終端回傳 framesDir。
4. `python tools/build_cleaning_animation_gifs.py <framesDir>` 以固定色盤封裝四份 384×256 GIF；各含54個來源畫面、總長5240 ms（含待機）。GIF 是匯出合成，非瀏覽器錄影。

檔案、Alpha、切格及匯出檢查只涵蓋對應項目。生成成功、自動檢查與瀏覽器有限檢視不能代替使用者對整段動畫的美術確認。正式流程／硬體不在本輪驗收範圍。

本輪驗證結果：6份RGBA atlas／28有效格／兩個透明空格檢查通過，4份GIF回讀皆384×256、54格、5240ms；共同播放器語法檢查與引用檢查通過。`tools/check_docs_links.py` 通過433個本地連結／82份Markdown（不檢查錨點或網路）。瀏覽器已載入全部素材、查看正常播放、暫停拖曳至2.45秒、日夜、慢速選項及減少動態；[沖洗畫面](browser-rinse-preview.png)是實際瀏覽器截圖。已還原正常速度、白天與循環播放。這些是有限檢視，不推定其他裝置或長時間播放驗收。
