## 快速上板測試版本

現有治療測試能觀察生病的傷心表情，但不會快速觸發其他三種原因或提醒冷卻；新增兩個專用環境：

- `esp32dev_sad_test`：成鳥，獨立 NVS `pet-sad-a`。
- `esp32dev_sad_baby_test`：幼鳥，獨立 NVS `pet-sad-b`。

冷開機／RESET 建立健康小鳥（心情 80、飽食度 80、清潔度 100）。初始化後約 8 秒、回到首頁且沒有音效時，自動設心情 40，應顯示傷心＋三條線，播放一次提示。此自動情境只執行一次；若先輸入有效情境指令則取消自動觸發。持續傷心不定時重播。提示冷卻僅此測試版縮為 **10 秒**；正式版仍是 **5 分鐘**。沒有加快生病／死亡或成長時程。

成鳥燒錄：

```powershell
& 'C:\Users\Student\.platformio\penv\Scripts\pio.exe' run -e esp32dev_sad_test -t upload
```

幼鳥燒錄：

```powershell
& 'C:\Users\Student\.platformio\penv\Scripts\pio.exe' run -e esp32dev_sad_baby_test -t upload
```

需要指定連接埠時，在命令末尾加 `--upload-port COM4`，依實際裝置連接埠調整。序列監控以 115200 開啟，輸入一個數字並送出；換行忽略：

- `0`：健康／正常，清除所有傷心原因，保留音效冷卻。
- `1`：只有心情 40；`6` 改為 44（應繼續傷心），`7` 改為 45（應解除）。
- `2`：只有飽食度 25，可用餵食驗收。
- `3`：只有清潔度 25，可用清潔驗收。
- `4`：只有生病，可用治療驗收；治療後沒有其他原因就恢復正常。
- `5`：心情 40、飽食度 25、清潔度 25，健康；只照顧其中一項仍傷心。
- `8`：只將飽食度／清潔度調為 29（已觸發原因仍保留）；`9` 改為 30（解除這兩項原因），心情／疾病保持原值。

例如收到第一次提醒後送 `0`、再送 `1`：新提醒等距離上次實際播放滿 10 秒才響；等待中送 `0`，就取消。睡眠中拒絕測試指令，透過原本休息／起床操作驗收靜音與醒來提醒。遊戲中可送 `1`，確認遊戲未被提示打斷，返回首頁後才播放。開機自動情境測的是「正常轉傷心」，並非載入傷心存檔；冷開機靜音已有原生測試覆蓋。

逐項測原因之前，先送 `0` 並等畫面回正常，再送目標數字；直接從一個傷心原因切換另一個原因仍屬持續傷心，不會再次提醒（新生病例外）。

## 實機檢查清單（供後續回歸）

1. 正常轉傷心時聽到一次柔和下降提示；持續傷心超過 5 分鐘保持安靜。實際音量與聽感依蜂鳴器確認。
2. 心情 ≤40、飽食度／清潔度 ≤25、生病各自觸發；心情到 45、飽食度／清潔度到 30 才解除各自原因。多種原因並存時，單項照顧後仍顯示傷心。
3. 幼鳥與成鳥兩幀的三條線位置和預覽一致；很髒時共用污漬正常疊加。餵食、清潔與治療恢復動畫優先，結束後顯示當下表情。
4. 遊戲／照顧動畫／其他音效期間不被提醒打斷；回主畫面後仍不舒服才提醒，已照顧好則取消。實際播放後 5 分鐘內的再次觸發先等冷卻完成。
5. 睡覺時安靜，正常睡眠或 Deep Sleep 醒來仍傷心時提醒一次（仍遵守冷卻）；正常重開機讀到傷心狀態不播放開機提醒。

本輪實機功能驗收以使用者上述回報為準；自動測試與總括實機回報不擴大為 BLE 長時間穩定性或存檔故障驗收。Deep Sleep 重新啟動會重建執行期冷卻；此提醒狀態未加入持久保存格式。
