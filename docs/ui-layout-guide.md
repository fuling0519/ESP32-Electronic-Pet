# 128×64 OLED 排版引導手冊

文件角色：OLED 排版規格；畫面驗收只記主台帳 A2-UI／A5-VIS。核對日期：2026-10-02；[最新進度](project-plan.md#progress)。

本手冊適用於本專案新增或修改的 OLED 畫面。修改 `src/ui/`、顯示字型或操作文案前先讀本文件。使用者明確指定的設計優先；例外須記錄原因與驗證結果。既有畫面不代表已符合全部規則，修改到該畫面時一併檢查。

## 1. 先安排整頁，再寫繪圖座標

每頁先定義一個主要目的，例如看寵物、看資料、做選擇。列出必要資訊、主要圖案與操作，再分配區域。裝飾圖案不可擠壓資訊與操作區。

動手前記下每個元素的 `(x, y, width, height)`；文字另記 baseline。至少檢查最長文字與全部選取狀態。不能只判斷「放得下」：還要看比例、對齊、空白和閱讀順序。

選單資訊塞不下時不用硬擠，可以新增分頁。保留字型可讀性與留白，讓頁碼及翻頁操作一致；不要為了把全部選項放在同頁而壓縮間距。已知的長按返回可以保留功能而省略提示。

### 資訊簡化與必須同頁時的處理

本專案優先採用直覺、容易辨識的圖示表達操作與狀態，例如食物代表餵食、音符代表聲音。先移除重複資訊，再考慮圖示；其餘內容若不需要同時閱讀，可分頁。圖示須在 OLED 原尺寸下仍能辨認，同一功能在不同頁面使用相同圖示。

當資訊確實必須同頁呈現時，依下列方向提出具體方案：

1. 優先用直覺圖示代替較長的標籤；意義不明確時搭配短中文，不讓玩家猜圖示意思。數值、名字及必要單位仍需保留。
2. 使用更簡短且意思完整的中文。
3. 使用玩家容易理解的簡單英文，例如 `Yes / No`，避免生硬縮寫。
4. 仍不足時，可詢問使用者是否接受較小的中文字型；提供原尺寸預覽，說明可多容納哪些資訊與可讀性取捨，再決定是否採用。

縮短中文、改用英文或圖示有多種合理表達且會影響理解時，也可以帶著具體版面詢問使用者偏好。既有且意義清楚的圖示與文案可直接沿用，不必每次重新確認。無論選哪個方案，都必須保留基本留白；不能以「必須同頁」為由讓文字重疊或貼框。

## 2. 像素邊界與留白

畫布座標為 `x=0..127`、`y=0..63`。一個寬 w 的矩形最右邊是 `x+w-1`；高 h 的矩形最下邊是 `y+h-1`。

| 項目 | 基本規則 |
| --- | --- |
| 外框 | 有外框時，邊線佔用 x=0、127 與 y=0、63 |
| 內容安全區 | 有外框的文字與獨立圖案原則上位於 x=3..124、y=3..60 |
| 距離外框 | 至少 2 個完整空白像素；文字最下方不得超過 y=60 |
| 文字行間 | 不同列的字圖之間至少 2 列空白，通常以 3～4 列較舒適 |
| 圖案與資料欄 | 至少 6 個空白像素，優先使用 8 個以上 |
| 碑內／框內文字 | 與圖案內側邊線至少 3 個空白像素，並檢查圓頂、斜邊 |
| 操作與內容 | 分成獨立區域，字圖間至少 2 列空白；不可共用同一塊空間 |

空白量按實際佔用範圍計算：上下兩元素的間距為 `下方元素 top - 上方元素 bottom - 1`。例如內容到 y=46、操作從 y=49 開始，中間 y=47、48 是兩列空白。

焦點框、底線等刻意相連的裝飾可例外；不能用這個例外合理化提示文字貼邊。

## 3. 字型、baseline 與字串長度

| 繪圖方式 | 水平方向預算 | 垂直方向注意事項 |
| --- | --- | --- |
| `drawText` | 現行 ASCII 字型每字前進 6px | y 是 baseline，實際字圖依字元而異 |
| `drawSmallText` | ASCII 每字前進 5px | y 是 baseline；小寫字母可能有下伸部分 |
| `drawUiText` | ASCII 6px，已收錄中文字與全形標點 12px | 中文字圖完整範圍為 y−11..y |
| `drawStatusText` | 使用 `statusTextWidth()` | 使用另一套字型，不能直接套用 UI 字圖高度 |

一般文字使用 6×10，中文預設使用現有 12×12 字圖；5×7 用於年齡、頁碼等次要資料。必須同頁且圖示、精簡文案仍不足時，可依第 1 節與使用者討論縮小中文字型。較小字型須重新檢查字圖可辨識性與所有相關間距，不直接縮放現有點陣造成筆畫消失。

中文字在 baseline 60 時佔 y=49..60，和底線 y=63 之間恰有兩列空白。ASCII baseline 不等於字圖最下方，需查看實際渲染，尤其是 `g/p/q/y`。混排取所有字元範圍的聯集。

混合中英文使用 `uiTextWidth()`，不要用 UTF-8 的 `strlen()` 算畫面寬度。`strlen()` 只可用於已保證 ASCII 的名稱。缺少字圖會顯示問號，新增中文或全形標點後必須補字集並重新產生字型。

顯示寬度與字串緩衝區容量分開計算：UTF-8 中文通常占 3 bytes，結尾還有 `\0`。例如六字母名字加「 孵化了！」為 90px、需要 20 bytes。

## 4. 畫面配置慣例

- 資料頁：標題與頁碼、分隔線、資料區、必要操作區。兩頁同一寵物資料都以寵物名字為標題；資料欄使用一致的左緣。
- 選單頁：選項共用左緣，`>` 有自己的欄位；全部選取狀態都要檢查。三列選單通常不再加底部提示；超出可用空間就新增分頁，並檢查首末頁及翻頁後的焦點位置。
- 確認頁：標題、操作對象、同一列的 `Yes / No`。左／右選擇，短按執行，長按返回；選取游標不可使文字跳動。預設選項要明確，目前刪除確認預設 Yes。
- 告別頁：墓碑是主體，姓名置於碑內；操作位於右下角獨立區域。依實際文字需要決定碑寬，不為假設中的長數值無限加寬。
- 墓園頁：左側墓碑作為辨識圖案，右側顯示姓名及年齡；刪除操作獨立一列。省略「目前寵物」等重複身分文字。
- 轉場頁：動畫區與訊息區分開預留。孵化訊息含名字，檢查每個動畫階段而非只看最後一格。

圖案需要不同大小時可調整幾何外框；使用者手繪寵物素材維持原像素比例，不為塞字而拉伸。墓碑要保留可辨識的圓頂、直身與底座。

## 6. 動態內容的邊界

至少檢查六字母名字（包含寬字形）、年齡的秒／分／時／天切換、最大頁碼 `33/33`、空墓園、可刪除與不可刪除紀錄、Yes 與 No 兩種焦點。

目前年齡顯示 `AGE 59s`、`AGE 59m`、`AGE 23h`、`AGE 9999d` 等。以 `AGE 9999d` 作常用長值樣本，但它不是儲存上限；異常或極大數值須另訂緊湊顯示方式並驗證，不能靠截斷字串或拉寬整個墓碑處理。舊存檔名稱若可能超過六字母，也必須納入版面檢查。

## 7. 修改與驗證流程

1. 讀本手冊、相關 render 函式及實際字型，列出必要資訊與輸入行為。
2. 先寫元素範圍表，檢查安全區、相鄰間距、最長文字及選取框。這是實作者的基本工作，不必每次請使用者核准座標。
3. 完成修改後，用實際字型與像素繪圖產生 128×64 預覽，或在實機查看；同時看原尺寸與整數倍、無平滑放大的版本。概念草圖只能討論配置，不能代替實際字圖驗證。
4. 檢查所有相關狀態與動畫幀：裁切、交疊、字圖缺失、視覺比例、提示貼邊、選取切換、短按及長按。
5. 編譯正式版與相關測試環境。編譯只確認程式可建置，不能當成排版通過的證據。
6. 交付時分別說明座標檢查、預覽檢查與實機回報。沒有實際渲染預覽或硬體可用時，明確記為「僅座標檢查，視覺待驗證」，不能宣稱排版已驗收。

使用者確認視覺後，把接受的配置記回本手冊，驗收結果及仍待驗證的行為只記主台帳；UI 接受不等於存檔持久化、斷電或全部遊戲流程驗收完成。
