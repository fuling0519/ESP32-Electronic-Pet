## 2026-09 歷史紀錄


- **2026-09-30**：取消大便生成、數量與保存玩法。清潔度四階段直接顯示 0～3 個髒污，Clean `+30` 後依新階段減少或消失；髒污已接入主畫面、餵食動畫與一般睡眠畫面。完成約 3 秒的幼鳥／成鳥餵食動畫與髒污預覽環境，程式及正式韌體編譯通過，正式韌體畫面仍待上板驗收。
- **2026-09-30**：完成手機與連線 Stage 2 唯讀 BLE 程式。ESP32 提供裝置資訊與完整寵物快照，Flutter 完成查詢、通知重組、驗證及斷線舊資料標示；PlatformIO 編譯、`flutter analyze` 與 Web Release Build 通過，BLE 實機驗收待完成。加入 BLE 後正式韌體 Flash 為 1,216,921／1,310,720 bytes（92.8%），僅餘約 93.8 KB；後續功能需優先處理 BLE 體積或分割區方案。
- **2026-09-29**：曾規劃定時大便與清除玩法；此方向已由 2026-09-30 決策取代，不再實作大便事件或保存。
- **2026-09-28**：完成一般睡眠首版程式並由使用者完成實機驗收。幼鳥與成鳥可從 Rest 進入睡眠，短按 SW 起床但睡眠畫面不顯示提示；原角色以可驗證的繪圖遮罩閉眼，旁邊獨立循環 `Z／Zz／Zzz`，並保留主畫面的側邊狀態圖示與底部等級線。睡眠期間年齡、飽食、清潔、六小時疾病門檻與生病後 24 小時死亡門檻照常推進，心情不下降並每 10 分鐘恢復 1，死亡可在睡眠中發生。入睡與起床立即保存，睡眠中重開機會醒來且不補算斷電時間。新增獨立 NVS 的 `esp32dev_sleep_test`：入睡時把飽食設為 0，每 10 秒恢復心情、20 秒生病、再 30 秒死亡，讓操作選單前不會提前開始疾病倒數。五個韌體環境全部編譯通過，睡眠畫面、起床、數值更新及睡夢中死亡均已上板確認；原生測試因本機無 host C++ 編譯器未執行。
- **2026-09-28**：使用者完成墓碑與重養流程上板驗收：死亡墓碑保存與瀏覽、二次確認刪除、ABB 自動命名、領養新蛋，以及重開機後保留目前寵物與墓碑均正常。此次回報不包含 32 筆滿額、寫入途中斷電、損毀槽回復或正式六小時／24 小時門檻測試；下一步規劃一般睡眠。
- **2026-09-28**：建立 [OLED 排版引導手冊](ui-layout-guide.md)，規定安全區、至少 2px 空白、字型與 baseline 計算、圖文比例、確認選項及修改前後檢查流程，並接入 README。記錄使用者接受的窄墓碑、上移操作與 Yes／No 配置；此回報僅確認 UI，未擴大為保存或斷電驗收。本次僅新增文件規範。
