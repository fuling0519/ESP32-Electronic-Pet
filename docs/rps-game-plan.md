# 猜拳小遊戲企劃 v0.1

更新日期：2026-10-02。狀態：首版在韌體 1.3.0 實作；目前 1.4.0 的 EXP／升級增量見 [規則及驗收](exp-level-plan.md)。首版基本操作及心情 BLE 即時同步已由使用者實機確認。特殊中斷與存檔邊界另行驗收，詳細進度見主台帳 A5-GAME。

2026-10-02 已改用使用者提供的手勢圖；三種手勢統一取自已修改剪刀的 `assets/games/rps/gestures.png`，均逐像素取出。以下記錄採用的回合、獎勵、版面及限制；進度仍統一記錄在 project-plan.md 的 A5-GAME。

## 1. 遊戲定位

玩家與自己的小鳥玩剪刀、石頭、布，完成一場約 20～35 秒的短互動。實際長度由玩家選招速度決定，不強迫限時選擇。

128×64 單色畫面每次只負責一件事：選招、倒數、揭曉或看總結果。遊戲期間不放主畫面的需求側欄，也不塞入完整 64×44 小鳥、兩隻手與三個選項。小鳥是對手；結果页以其既有 ASCII 名字識別，不需把鳥翅畫成人手。

首版包含一種玩法、三回合、結算與再玩。連勝、難度、道具、排行榜、逐局歷史及手機控制留待後續。

## 2. 入口與可玩條件

- 主選單沿用「陪玩」入口，進入「猜拳」準備頁；未來第二個遊戲完成後再增加遊戲選擇頁。
- 猜拳取代原本按一下心情 +15 的陪玩行為，同一入口只使用遊戲結算獎勵。
- 幼鳥與成鳥、清醒且健康時可開始。心情已滿仍可遊玩。
- 蛋顯示「等待孵化」；生病顯示「請先治療」。死亡沿用既有死亡流程。
- 飽食與清潔偏低不直接禁止遊玩，時間與疾病仍正常推進。此規則不新增體力或入場費。
- 準備頁顯示「猜拳」「共三回合」「按下開始」；長按返回主選單，焦點留在陪玩。

## 3. 勝負規則

1. 每場固定三回合，每回合雙方各出一招。
2. 石頭勝剪刀，剪刀勝布，布勝石頭；相同為平手。
3. 平手也消耗一回合，不加賽。
4. 三回合後比較雙方勝場數，較多者獲勝，相同則整場平手。例如一勝一敗一和為整場平手。
5. 即使前兩回合已分出總勝負，仍玩完第三回合，維持規則與畫面一致。
6. 小鳥每回合獨立、等機率選擇三招，不依玩家選擇、心情或前局結果調整。可連續出相同招式。
7. 小鳥的招式在每回合選招頁出現前就抽好並保留；玩家切換選項、畫面重繪與倒數不重新抽取。

純隨機猜拳不提供可學習的對手策略；首版樂趣來自短互動、揭曉與養成回饋。若之後希望增加技巧，再另提「觀察小鳥出拳習慣」玩法。

## 4. 操作與每回合節奏

- 左／右在「剪刀、石頭、布」間切換，兩端停住、不循環；上／下不作用。
- 第一回合預選石頭，後續回合保留上一回合玩家選擇。短按 SW 鎖定。
- 選擇沒有時間限制，不因猶豫而判輸；閒置期間養成計時照常。
- 鎖定後顯示 3、2、1，各 350ms，共 1.05 秒，然後同時揭曉。
- 揭曉顯示雙方出拳與「你贏了／平手／你輸了」，至少停留 800ms；之後短按進下一回合，第三回合則進總結果。
- 揭曉不自動消失，讓玩家有時間看懂。早於 800ms 的短按丟棄、不排隊；需重新按下才能前進。
- 揭曉後消耗造成切頁的按鍵事件；持續按住或方向連發不得在下一頁自動鎖定出拳。
- 各頁長按 SW 返回主選單。未完成三回合者不發獎勵；已完成者保留已結算的獎勵。

## 5. 128×64 畫面配置

以下為實作座標，已用同一 UiController、U8g2 ASCII 字型及專案中文字圖產生 [畫面預覽](rps-game-preview.png)，原尺寸檔在 `.pio/rps-preview/`；已檢查三種焦點、倒數、勝負、獎勵、最長 8 字元名字與禁止進入頁。使用者已回報基本實機操作正常，各特殊情境仍依驗收文件追蹤。採現有 12×12 中文與 6px 前進寬度的 ASCII 字型；外框佔 x=0/127、y=0/63，內容維持 x=3..124、y=3..60。

### A. 準備頁

- 「猜拳」置中，baseline 15，字圖 y=4..15。
- 分隔線 (6,20) 到 (121,20)。
- 「共三回合」置中，baseline 38，字圖 y=27..38。
- 「按下開始」置中，baseline 58，字圖 y=47..58。
- 長按返回沿用全專案操作，不額外塞提示。

### B. 選招頁

- 左上「猜拳」在 (6,15)，右上 `1/3` 在 (102,15)。
- 中間三張 32×24 選招框，左上角分別為 (8,23)、(48,23)、(88,23)。框內使用 24×18 單色圖案，位置為 (12,26)、(52,26)、(92,26)。
- 選中框使用實線框，其餘不畫框；圖案不反白，避免細節消失。
- 圖案分别為剪刀手、拳頭與張開的手。它們是招式符號，不修改既有小鳥素材。
- 底部只顯示目前選擇的中文名稱，如「石頭」，置中、baseline 60，字圖 y=49..60。選取框底邊 y=46，保留 y=47..48 兩列空白。
- 短按確認只需在準備／首次教學說明；選招頁不加冗長提示。若實測新玩家不知道左右選擇，改底部為「左右選擇」並在上方顯示選中招式名稱，需重新排版驗證。

### C. 倒數頁

- 左上保留「猜拳」，右上保留回合數。
- 中央以像素線段繪製 12×20 的 3／2／1，置於 (58,26)，不引入整套大字型。
- 不顯示對手招式；鎖定後方向與短按均不改變結果。
- 每拍可播放短音，沿用非阻塞音序；靜音設定如未提供，不在本功能新增設定頁。

### D. 揭曉頁

- 左欄「你」在 (23,15)；右欄為寵物名字，於 x=94 置中。以舊存檔最長 8 個 ASCII 字元計算，範圍 x=70..117，仍在安全區內。
- 左右 24×18 手勢置於 (17,25)、(82,25)。圖案大小與選招頁相同，但只保留兩個圖案及更大空白。
- 中間 `VS` 位於 (58,37)，不得與左右圖案交疊。
- 底部「你贏了／平手／你輸了」置中，baseline 60，字圖 y=49..60，距手勢底部 y=42 有六列留白。
- 圖案下方不再塞雙方招式中文或總比分；需要時停留閱讀，短按下一回合。

### E. 總結果頁與再玩頁

- 總結果頁：「你贏了／平手／你輸了」置中，baseline 15。
- 第二列只顯示「2:1」，baseline 29，左邊是玩家勝場、右邊是小鳥勝場；不加「勝」字，避免比分相同時誤認為獲勝。
- 第三列「心情 +15」置中，baseline 45，顯示實際增加量；第四列 EXP +15，baseline 60。
- 結果頁停留至短按；長按返回。有升級則先播放兩秒慶祝，之後才提供「再玩」「返回」；沒有升級直接進再玩頁。
- 再玩頁標題「再玩？」baseline 15；兩個選項 baseline 36、56，上／下選擇，短按執行，預設「返回」。長按返回主選單。

## 6. 獎勵與養成整合

- 整場獲勝：心情 +15；平手：+10；落敗：+5。輸了仍得到陪伴回饋，不扣心情。
- 只在第三回合揭曉時結算一次；按下一頁、長按退出、重繪、BLE 查詢與再玩都不可再發同一場獎勵。
- 心情最多 100，結果顯示實際增加量。例如 96 心情獲勝顯示 +4，滿值顯示 +0。
- 1.4.0 起同一次結算發放勝／和／敗 15／10／5 EXP，心情滿值仍可拿 EXP；升級、滿等及結果頁後兩秒慶祝見 [經驗規則](exp-level-plan.md)。不額外扣飽食／清潔，原有自然衰減照常。
- 不加每日次數或冷卻。現有專案沒有可信日曆基準，也不需要為第一個遊戲新增每日重置資料。
- 完成時透過應用層更新唯一 PetData，沿用存檔機制及 BLE 狀態通知；不新增 BLE 命令、遊戲歷史或存檔欄位。
- 結算後標記待保存；依現有儲存節奏寫入。保存前立即斷電可能失去這次獎勵，不能承諾每場即時持久化。開機不恢復未完成比賽，也不重播或補發獎勵。

## 7. 中斷與優先順序

每個主迴圈先更新寵物時間與健康，再處理遊戲事件，避免死亡與結算同時發生時仍發獎勵。

- 死亡：立即終止遊戲，走現有死亡／墓碑流程；尚未結算的場次不發獎勵。
- 遊戲中生病：終止未結算場次，停留「請先治療」提示頁，長按返回。已結算的獎勵不追回。
- 遊戲中長大：終止未結算場次，播放既有成長轉場；已結算獎勵保留。此罕見情境先採明確取消，避免轉場回復錯誤。
- 長按退出：不彈出確認，返回主選單；操作說明需明列未完成不結算，首版 OLED 準備頁保持三行配置。
- BLE 斷線／重連：不影響本機遊戲；主迴圈繼續處理 BLE。
- 睡眠：遊戲頁沒有睡眠入口；離開後才能進入休息。未來加入自動睡眠時需另訂遊戲閒置策略。
- 重開機／斷電：載入原本有效寵物存檔並回主畫面，當前場次丟棄。

## 8. 素材與程式分工

- 三種手勢來源均為使用者已修改剪刀的 `assets/games/rps/gestures.png`。48×36 圖檔的左上／右上／左下分別是布／石頭／剪刀，各 24×18；右下空白不使用。`tools/generate_rps_icons.py` 保留原像素與透明背景，不縮放或重繪；白色不透明像素轉為 OLED 亮點。圖像資料共 162 bytes，輸出至 `src/ui/RpsIcons.h`，原尺寸及四倍無平滑預覽為 `docs/rps-icons-preview.png`。
- 補足實際使用的中文字集，例如猜、拳、剪、刀、石、頭、布、贏、輸、回、合等；以最終文案差集為準。
- `src/games/RpsGame` 維護招式、回合、比分、階段計時與待取出的單次結果；勝負規則獨立於硬體，方便原生測試。
- UiController 負責選單、繪圖與輸入轉換；Application 負責領取一次性結果、驗證寵物狀態、發獎勵與保存。
- 所有等待用時間差推進，不使用阻塞延遲。結果計算與亂數抽取不得放在 render 中。
- 隨機来源由應用層提供，測試能注入固定出拳序列，實機用 ESP32 亂數並作等機率映射。
- 首版不新增大型圖庫或通訊依賴，完成後記錄正式韌體 Flash／RAM 增量，並量測遊戲與 BLE 同時運作的 heap。

## 9. 開發順序

1. 確認三種手勢在原尺寸可辨識；用實際字型產生準備、選招、揭曉及總結果的 128×64 預覽。
2. 實作純遊戲規則及九種出拳組合測試，完成三回合累計與一次性結果。
3. 接入操作、倒數、畫面與音效，處理長按、早按和跨頁殘留輸入。
4. 接入健康檢查、心情獎勵、保存與 BLE；加入死亡／生病／成長中斷測試。
5. 編譯正式版與受影響測試環境，記錄容量，再做實機操作與連線回歸。

## 10. 驗收清單

- 九種出拳配對全部正確；三回合必結束，含三次平手及前兩回合已領先兩勝。
- 未確認不能前進；倒數中方向或短按不改招式；揭曉早按不跳頁；長按不帶出短按副作用。
- 三個選取狀態、所有勝負文案、8 字元舊名字與心情 +0 均無裁切、缺字或重疊。
- 原尺寸手勢可辨識，並以整數倍無平滑預覽核對像素邊界；最終以 OLED 實機閱讀為準。
- 獎勵為 15／10／5 並限制於 100；退出未完成場次不加值；停留、切頁及重連不重複結算。
- 蛋／生病不可開始；中途生病、死亡與成長按規則中斷，存檔與墓碑流程正常。
- 儲存完成後重開機保留心情；未完成場次重開機不補發；保存失敗不重新結算。
- 遊戲時 BLE 查詢與狀態通知正常，長時間玩不使按鍵或音效卡住。
- 可連續完成十場、任意回合退出、再進入遊戲；回合／比分／結算旗標正確重設。

完成定義：一場完整可玩的猜拳、可退出可再玩、獎勵正確且不重複、已保存資料可續用、畫面及基本 BLE 並行通過實機確認。首版 1.3.0 的完成條件不含經驗值／升級；1.4.0 增量另依 A3-EXP 驗收。
