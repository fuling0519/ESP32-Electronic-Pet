# 心情與基本需求連動：驗證與上板步驟

日期：2026-10-03。玩法見 [企劃第 4.2.1 節](project-plan.md#421-心情與基本需求連動2026-10-03-已確認)，唯一進度台帳為 A3-MOOD。

## 計時與邊界

- 飽食度／清潔度 ≤50 各增加一次清醒扣分，成鳥每 20 分鐘、幼鳥每 2 分鐘扣 1／2／3；同秒發生需求下降與心情扣分時，先下降需求，再依當下需求扣心情。
- 正式版睡眠正常每 20 分鐘 +1，一項低需求每 40 分鐘 +1，兩項低需求暫停。跨門檻時，先按變化前的狀態結算已經過的時間，後續時間採新速率；一般／Deep Sleep 共用同一核心。
- 恢復進度採整數單位：正常每秒累積 2、一項低需求累積 1、兩項低需求累積 0，累積 2400 單位恢復 1 點。正常睡 10 分鐘後改成一項低需求，再睡 20 分鐘即可恢復 1 點。
- 暫停恢復不清除已累積進度；持續供電跨多次短睡保留，RTC 跨 Deep Sleep 保留，正常重開機／斷電清除未滿一點的進度。NVS V1 不增加欄位；RTC 識別碼更新，拒絕把舊版秒數當作新版進度。
- `esp32dev_sleep_test`／`esp32dev_deep_sleep_test` 仍使用加速恢復：正常每 10 秒 +1、一項低需求每 20 秒 +1、兩項暫停。正式版是 20／40 分鐘。

## 自動驗證

`test/mood_native.cpp` 包含兩階段 50／51 邊界與餵食／清潔恢復、同秒事件、三種睡眠速率、暫停及奇數進度的 RTC 領域還原、跨門檻的獨立預期值、上下限、死亡截斷，以及 20 種初始狀態的一次性 48 小時更新對照逐秒更新（涵蓋成長、疾病與死亡）。

由 `tools/test_rps.ps1` 執行心情、寵物核心、猜拳領域及實際 UI 回歸。韌體使用正式、一般睡眠測試及 Deep Sleep 測試三環境編譯。結果與紀錄只在 A3-MOOD 維護；原生測試不模擬 RTC／NVS／BLE 硬體。

## 上板驗收

使用專案既有 PlatformIO 工具；若本機已有 `.pio/verification-packages`，沿用隔離框架與建置目錄：

```powershell
$petPio = 'C:\Users\fulin\.platformio\penv\Scripts\platformio.exe'
if (Test-Path '.pio/verification-packages') {
    $env:PLATFORMIO_PACKAGES_DIR = Join-Path (Get-Location) '.pio/verification-packages'
    $env:PLATFORMIO_BUILD_DIR = Join-Path (Get-Location) '.pio/verification-build'
}
& $petPio run -e esp32dev -t upload
```

1. 保留正式寵物存檔，不 erase flash。先查看階段、心情、飽食與清潔；等待下一個完整清醒週期，依當時需求確認扣分。既有餘數會影響第一次扣分時間。
2. 需求降到 50 後觀察倍率；餵食／清潔讓需求回到 >50，再觀察倍率恢復。遊戲仍應依贏／和／輸給 +15／+10／+5，最多 100。
3. 需求都 >50 且心情未滿時，一般睡眠累積 20 分鐘應恢復 1；中途若需求跨過 50，依各段速率計算。兩項都 ≤50 時睡眠不恢復心情。
4. 重複短睡確認進度累積，省電睡眠後用 SW 喚醒，確認心情、年齡及需求一致，手機重新連線後收到新數值。真正重開機／斷電不保留未滿一點的恢復進度，也不補算未知斷電時間。
5. 快速確認硬體睡眠流程可改燒 `esp32dev_deep_sleep_test`，沿用 [深睡驗收](deep-sleep-test.md) 的 60 秒 Timer／SW 步驟與獨立 `pet-deep` 存檔；低需求會減速或暫停，不能一律期待 60 秒增加 6 點。測完燒回正式版。
