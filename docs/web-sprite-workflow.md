# Web 寵物精靈圖製作規則

用途：供不同寵物、角色與成長階段共用，沿用已確認的美術與動作決策，減少重複討論。第 1～8 節是通用規則；第 9 節獨立記錄小龍設定，不自動套用到其他角色。當次使用者指示優先於本文件；新角色、新物種或新成長階段不能直接視為已確認。

## 1. 開始前先查現況

- 先讀本文件、對應素材目錄的 README 與現有 Web 繪製程式，盤點已完成、已確認、未完成的素材。
- 分清「造型已確認」「單組動畫已確認」「已接入 Web」「整合後已驗收」，不能彼此代替。
- 先開啟真正要附給繪圖工具的參考圖，確認版本，再開始生成。
- 檔案已存在時，先嘗試可用的圖片傳遞方式。工具不接受某種路徑，不代表檔案不存在；不要直接要求重新上傳，也不要只靠文字猜造型。

## 2. 美術基準固定

- 每個角色先確定自己的主要參考、固定特徵與美術風格；Web 角色應具備與目標場景相稱的配色、明暗和材質層次。
- 若來源包含韌體單色圖，僅將它作為輪廓、體型、頭身比例與角色特徵參考。Web 素材另行製作，不直接套色塊，也不沿用硬體的解析度、畫格數、播放速度或像素位移限制。
- 同一角色固定五官、輪廓、肢體結構、主要配色、材質、描邊、光源與細節密度；角、耳、翅膀、尾巴等特徵只在該角色本來就有時保留。
- 不擅自套用其他角色的眼型、配色、裝飾或頭身比例。優先附一張清楚的主要參考；只有視角或動作確實需要時，才補充已確認參考。
- 跨角色共用的是製作方法與品質要求；具體造型和姿勢依各角色設定處理。

## 3. 狀態與動作設計

- 先列出該角色需要的狀態，定義各狀態的情緒、姿勢、可動部位，以及與相似狀態的區別。不要求每個角色都有相同的肢體或移動方式。
- 同一狀態可以依角色習性採用不同姿態；睡眠、生病、傷心與死亡等容易混淆的狀態，要能透過表情、身體支撐、動作及獨立效果辨認。
- 待機、互動與移動分別設計動作氣質和幅度；不把移動的大幅動作誤套進休息狀態。
- 動作設計應符合已確認的肢體結構，不為了表演動作擅自增加或省略肢體。
- 角色畫格與食物、道具、符號、光效等效果分開規劃；是否跨角色共用，依專案設定決定，不為每個角色重製已存在的共用效果。
- 專屬角色決策集中記錄在各角色段落或素材說明，不散落在通用規則中。

## 4. 提示詞寫法

依序寫清楚六件事：**參考與固定特徵 → 動作氣質 → 哪些部位能動 → 各格連續變化 → 哪些部位固定 → 排列與透明輸出**。

- 每次只處理一組明確動作；不把姿勢差異很大的睡眠、死亡、飛行硬塞進同一張圖集。
- 用可見的相對位置描述幅度，例如「身體留在原位，只有末端輕微舒展」。避免只有「高位／低位」「大一點／小一點」而沒有姿態基準的描述。
- 未定義並驗證基礎網格時，不使用「移動一個邏輯像素」或看似精確的像素承諾。
- 每格交代它與前一格的關係；循環最後一格要能自然接回第一格。
- 不動的部位要明確列出。需要局部呼吸時，不用「全身完全相同」與之矛盾。
- 只寫繪圖工具需要的視覺要求。不把專案歷史、韌體限制、播放程式或與畫面無關的解釋塞進提示詞。
- 若使用者只要求提示詞，交付文字即可，不呼叫繪圖工具。

## 5. 圖集與動畫規則

- 可以一個動作一份圖集；檔案數量不是整合難點，不必追求一張巨型圖集。
- 各動作的畫格數依動作複雜度與過渡需要決定，已有確認版本則沿用；不把某個角色的格數當成所有角色的規格。
- 同一動畫固定視角、角色比例、光源、配色、畫布與定位基準；不逐格重新縮放來塞滿格子。
- 依姿態設定穩定錨點，例如腳底、身體接地處或懸浮中心。不同姿態可有自然的寬高差異，不拉伸成相同外框。
- 保留該角色完整的輪廓、肢體與附屬特徵，四周留透明空間；不畫背景、地面、投影、格線、文字或編號，除非當次明確要求。
- 輸出真正帶 Alpha 的 PNG。棋盤格外觀不能當作透明證據，生成工具也不能保證每格定位精確。
- 播放速度依 Web 的自然程度設定，可用不同畫格停留時間；不要把眨眼做成每格等長，也不要把睡眠呼吸做得急促。
- 若兩格動畫仍然僵硬，先判斷是否缺少過渡畫格；不靠整隻角色的拉伸或縮放假裝新增姿勢。

## 6. 固定工作流程

1. **盤點與選參考**：確認這次要新增的狀態、已有決策與缺少的素材。
2. **最小批次生成**：依既定規則生成一組；畫格數盡量精簡，避免一次製作整套後才發現造型偏移。
3. **先看圖再整理**：檢查角色一致性、肢體、表情、動作幅度與完整構圖。明顯偏離要求時先修正，不把問題交給使用者反覆指出。
4. **整理素材**：保留來源圖；切格、平移對齊、補透明留白，記錄畫格座標、錨點與停留時間。整理不等於任意重畫、去背、改色或拉伸。
5. **使用共同繪製程式預覽**：更新對應角色的統一狀態預覽與相應動畫預覽，確認實際顯示尺寸、目標背景、狀態切換和減少動態模式。不可只看生成大圖；預覽應使用正式整合相同的繪製邏輯。
6. **接入已授權的對應流程**：當使用者要求製作並實作新素材時，預設完成整理、共同預覽及既有對應狀態的 Web 接入；若當次限定只做圖或獨立預覽，就依限定範圍交付。
7. **交付並標明邊界**：提供可查看的檔案／入口，說明已生成、已整合、已測試和仍待確認的部分。生成後不能只說完成，卻讓素材留在無法接續的臨時位置。

素材放在專案的 `web-preview/assets/pets/<物種>/<階段>/`；程式使用對應資料描述圖源、切格、定位與節奏。保留已確認版本，新版本驗證後再切換，不覆寫韌體原圖。更新必要的素材說明與計畫狀態；沒有明確指示就不 commit／push。

## 7. 哪些事需要再次討論

- **直接沿用**：已確認的角色設計、配色、狀態意義、動作氣質、透明背景，以及既有共用效果的分工。
- **自行處理並回報**：切格方式、檔名、定位、合理的初始播放節奏、預覽與程式銜接。不要為每個小步驟重新索取確認。
- **一次提出關鍵差異**：需要更改造型／美術風格、對未定動作有明顯不同的解讀、增加會改變遊戲規則的行為，或缺少無法替代的參考時，再討論。先指出推薦方案及其影響，不重問已確認事項。
- 同一組動作若出現相同問題，不只重複生成；先找出造成誤解的提示詞或參考，修正後再做。

## 8. 驗證與回報底線

- 檔案檢查：尺寸、透明通道、格數、切格範圍、完整輪廓與路徑正確。
- 動畫檢查：定位穩定、循環連貫、幅度合理、沒有無關色塊閃動、沒有靠整體縮放製造動作。
- 整合檢查：使用真正的狀態入口；分清睡眠／生病／傷心；確認互動、死亡、成長及紀念冊中適用的圖源；視覺預覽不改養成數值或存檔。
- 自動測試只能證明所覆蓋的程式行為，不能代替美術確認、瀏覽器實際播放或硬體驗收。
- 若無法實際打開瀏覽器驗證，直接標示限制並提供本機入口；不把語法檢查、圖片生成成功或測試通過說成「動畫看過且自然」。

下次可直接使用：

> 請依 `docs/web-sprite-workflow.md` 製作【角色／物種】的【成長階段】【動作名稱】。沿用該角色已確認的造型與設定，完成素材整理、共同預覽及對應 Web 接入；只在出現新的關鍵設計選擇時再討論。

## 9. 小龍專屬設定與現況

本節只適用於小龍。成年設定不能直接視為幼年版本已確認；其他角色不自動沿用下列造型、姿勢、表情、格數或移動方式。

### 造型與參考

- 成年主要參考：`web-preview/assets/pets/wyvern/adult/idle-preview-v1.png`。
- 成年側面飛行參考：同目錄 `flight-three-quarter-preview-v1.png`。
- 固定紫色圓臉、小豆眼、小嘴、腮紅、奶油角、額前突起、粉紫耳內、分節腹部、短小四肢、小翅膀與尾巴；維持相同描邊、光源與彩色像素風格。
- 不放大眼睛、不增加黃色口鼻面罩、不更換頭身比例。待機描述為翅膀留在身側、翼尖與翅膜小幅收放，不用「高位／低位」引導大幅拍翼。

### 成年動作設定

| 狀態 | 已定方向 | 不應混淆的地方 |
|---|---|---|
| 待機 | 雙腳著地，翅膀留在身側，翼尖與翅膜輕柔收放 | 不把整片翅膀抬到耳旁、頭後或頭頂；不呈現用力起飛 |
| 傷心 | 委屈眉眼、小嘴下垂，翅膀低垂並稍收攏 | 與疲倦的生病分開；不自行加眼淚或符號 |
| 生病 | 半睜眼、疲倦，翅膀鬆垂且更貼近身體 | 紫色皮膚不變；不靠醫療道具或變色表示 |
| 開心／摸頭 | 小小微笑、臉頰略提起，閉眼時是滿足笑眼，翅膀輕展 | 不大笑、露牙或大幅展翼 |
| 睡眠 | 趴著蜷縮、頭枕前爪、尾巴環身、雙翼收好，臉仍可見 | 靠背部與腹側的細微起伏表現呼吸，不讓整隻龍浮動 |
| 死亡 | 側躺，頭側靠地面，前爪鬆放，翅膀和尾巴自然攤落；自然閉眼、嘴角微垂、眉毛放鬆 | 不用 XX 眼、不皺眉；不畫成頭枕前爪的舒適蜷睡；身體靜止 |
| 被戳 | 嚇一跳 | 不是生氣；專用角色畫格仍待製作 |
| 飛行 | 使用已確認的側面造型，低空移動；可比待機有更明顯的拍翼 | 目前只有靜態造型，不能當作飛行連續畫格已完成 |
| 吃飯 | 專用動作尚待設計，延續已確認造型 | 目前待機配食碗是過渡呈現，不代表吃飯動畫已完成 |

### 既有素材與整合

- 成年待機四格；傷心、生病、開心各兩格；睡眠兩格；死亡一格。這是小龍目前素材的規格，不限制其他角色。
- 統一預覽入口：`web-preview/wyvern-states-preview.html`。對應素材、確認狀態與最新整合進度見 `web-preview/assets/pets/wyvern/adult/README.md`；本節現況記錄於 2026-10-21，繼續製作前仍須核對最新紀錄。
- 食碗、藥水、愛心、Zzz、清潔、升級與靈魂維持獨立效果。專案現有靈魂由各寵物共用，不畫進小龍死亡圖；共用靈魂新版仍待製作。
